# iroh 设备身份与连接

本文是操作和配置说明。整体职责见 [端与云服务架构](system-architecture.md)，
详细请求顺序与失败分支见 [交互时序](interaction-sequences.md)。

Linkport 在进程内运行 iroh，不需要账号、第三方 VPN 或系统级虚拟网卡。
根目录与桌面模块统一使用 Go 1.26.11，固定依赖社区实现
`github.com/tmc/go-iroh v0.3.0`。该实现并非 n0 官方 SDK；Go API 在 v1 前
不保证稳定，升级时应重新验证直连、中继、配对、撤销和跨平台行为。

## 添加自己的机器

1. 在两端启动 Linkport。
2. 在 A 的页头或状态栏选择「添加设备」，点击「生成配对邀请」。
3. 将完整邀请通过可信渠道发送到 B，在 B 的设备管理中粘贴并添加。
4. 双方验证 iroh 握手的公钥后保存信任关系。邀请只使用一次，八小时后
   失效；重新生成邀请会使旧邀请失效，退出进程也会清除邀请。
5. 在共享端显式选择串口，使用端刷新清单后连接。配对不自动共享串口。

邀请包含设备公钥、连接地址和随机 256 位令牌，不包含私钥。持有有效邀请
的人能够配对该设备，因此不要公开发布邀请。普通 iroh endpoint ticket
本身仅是连接信息，不是 Linkport 的配对授权。

导入时兼容消息软件添加的换行、空格和不可见分隔符，仍严格检查编码、版本、有效期、
公钥与 ticket 的一致性。错误会区分前缀缺失、内容截断、过期和系统时间异常。
使用八小时邀请时，两端都应更新到支持此有效期的构建；旧版接收端只接受五分钟邀请。

未知设备默认无法通过握手。邀请有效期内允许尝试配对，但业务 API 仍然
拒绝未配对公钥。配对请求中的公钥必须与真实握手身份一致，不采信 HTTP
头或请求体自称的身份。每个流先执行新的随机挑战，再进入 HTTP/RFC 2217，
避免会话恢复中的旧数据重放触发业务操作。

## 密钥保存、移除和重置

系统用户配置目录的 `linkport/devices.json` 包含：

- 独立生成的本机 Ed25519 私钥 seed 与名称。
- 已配对设备的公钥、名称、地址 ticket 和添加时间。
- 中继模式与地址发现配置。

Unix 上该文件权限为 `0600`，目录新建权限为 `0700`；Windows 使用用户配置
目录的继承 ACL。当前不是系统钥匙串存储。保存采用临时文件、同步和原子替换，
并持有进程锁，避免多个实例互相覆盖信任名单。无法读取或损坏时会报错，
不会静默生成另一身份覆盖原文件。

备份此文件等同备份本机身份，必须保密。不要把它复制到另一台机器上共用
身份；每台机器应自行生成密钥并通过邀请配对。公钥/设备 ID 可以展示和核验，
私钥不返回给桌面网页，也不发布到中继或地址发现服务。

「移除并断开」删除本机对该公钥的信任，立即关闭它的连接及串口会话，并
拒绝后续访问。另一端可能还保留旧设备条目，但无法据此绕过本机撤销。

「重置本机身份」要求输入完整的当前设备 ID，生成新密钥并清空本机信任名单，
立即暂停网络。重启后应在其他机器移除旧设备并重新配对。本机重置不能远程
撤销其他机器对旧公钥的信任；旧密钥泄漏时必须在各个对端移除旧公钥。

## 连接与网络服务

默认模式使用 Linkport 维护者签名目录中的中继和公共 pkarr/DNS 地址发现，同时使用局域网 mDNS。
公开地址记录只包含中继地址，不发布串口、日志、信任名单或私有 LAN 地址。
配对邀请可以包含直接地址；只应通过可信渠道分享。

设备目录来自本机信任名单，在线状态来自实际服务探测，不把「接在某个中继」
直接当成「串口可用」。临时探测失败不会终止仍正常传输的数据会话。缓存
地址不可达时按公钥重新解析。底层支持直连、中继兜底和路径变化；串口
会话真正断开后，当前版本仍由用户手动重新连接。

同一对设备复用经过身份验证的 QUIC 连接，在其中建立独立双向流承载探测与
各条串口会话。无论哪一端最先建立连接，双方都接收对端主动发起的流；关闭
一个流不影响其他会话。移除设备或关闭网络则终止整条连接及其全部流。

设备管理中的网络设置支持：

| 模式 | 行为 |
| --- | --- |
| 公共中继 | 维护者签名目录中的 HTTPS 中继、配对协同发现与公共地址发现 |
| 仅直连 | 不连接公共中继、不访问公共地址发现，使用直接地址与局域网发现 |

网络设置保存后立即关闭旧端点和发现服务，重启 Linkport 后应用。本机串口
监听继续工作。跨互联网的仅直连模式取决于地址可达性，不能保证穿过所有 NAT。
用户不能填写自定义中继或发现服务地址；旧配置在启动时迁移，保留身份和配对。

中继转发密文，能够观察连接与流量元数据，不能读取串口内容。
项目已部署东京 `https://207.148.110.58`；公网验证范围见 [部署记录](relay-deployment.md)。
公共中继目录使用独立签名密钥，不从配对设备公告自动添加任意中继。

## 无桌面的机器

```sh
# A：生成邀请并保持在线等待配对；Ctrl-C 结束邀请进程。
go run ./cmd/linkport invite

# B：在另一台机器导入邀请。
go run ./cmd/linkport pair 'linkport1.完整邀请'

# A/B：查看公钥与配对名单，启动共享服务。
go run ./cmd/linkport identity
go run ./cmd/linkport devices
go run ./cmd/linkport serve
```

`--directory DIR` 为设备管理命令选择隔离配置目录。设备管理命令需要独占
该目录；桌面或共享端正在运行时，应使用桌面入口，或者先退出对应进程。
串口 `share` / `unshare` 命令仍可更新共享规则，运行中的共享端会读取变化。

```sh
go run ./cmd/linkport forget DEVICE_ID
go run ./cmd/linkport network --relay-mode disabled
go run ./cmd/linkport network --relay-mode default
go run ./cmd/linkport identity --reset --confirm FULL_CURRENT_DEVICE_ID
```

`serve --local-api` 保留 loopback 只读开发接口；它与真实 iroh 共享服务用途不同。
本地桌面管理 API 继续要求每次启动随机生成的 `X-Linkport-Token`。

## 验证范围

自动化测试覆盖持久化身份与进程锁、邀请过期/篡改/单次使用、双方公钥绑定、
未授权清单拒绝、活动流撤销、身份重置、本机临时中继上的纯中继传输，以及真实 loopback iroh 通道上的
PTY 二进制收发与物理端口释放。浏览器测试覆盖设备管理和已有串口操作。
CI 保留 Windows/Linux/macOS 原生构建与测试。

仍需在目标环境验证真实跨网络 NAT、公共和自建中继、不同版本 Rust iroh
互通、实际 USB 串口及 Windows com0com 驱动。交叉编译不能代替这些运行验证。

## Desktop 协同发现与维护者中继

设备通过已配对通道交换签名联系方式并缓存；旧地址失败时可以向其他已配对设备查询。
公共中继固定为应用内置签名目录中的东京节点 `207.148.110.58:443`，普通用户界面
不提供自定义中继或本机公网监听设置。当前不获取远程目录，不使用旧目录缓存，
节点增减随应用更新。具体维护流程见 [目录维护说明](relay-directory.md)。
同源中继模块仍可以被维护者程序嵌入或独立运行。多中继恢复的边界见 [中继与协同发现](relay.md)。

应用版本仍有更新提示。后台自动更新开启时，应用包校验后暂存、等待重启；
关闭自动更新仍可检查并手动操作。中继配置显示“随应用更新”，保留内置签名校验，
不单独轮询或应用目录。仅直连模式继续禁止使用公共中继。
