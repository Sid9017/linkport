## 仓库规则

根目录 [AGENTS.md](../AGENTS.md) 的 `Code Review Rules` 包含：

- 使用中文描述可复现的问题、触发条件、影响与相关改动。
- 核对真实握手公钥、邀请的有效期和单次使用、私钥不泄漏、撤销后访问不可恢复。
- 核对双向 QUIC 流接收、独立会话关闭、物理端口独占、二进制与参数确认。
- 核对本机管理 token、临时探测失败、本机监听独立性和平台限制。
- 区分真实设备测试、浏览器 fixture、交叉编译与目标平台运行验证。

本地文件不会自动同步到 GitHub。应让规则进入被审查的仓库版本，并核对云端是否能够读取。
仓库目前的默认分支尚未包含本次工作区中新增的文件。

## 第一次真实验收

1. 将需要审查的代码与规则推送到远端分支，创建一个目标分支明确的 PR。
2. 检查 Codex 是否自动开始响应。
3. 如需手动请求，在该 PR 下评论：

   ```text
   @codex review
   ```

4. 等待最终审查反馈；没有问题也应以机器人给出的完成信号为依据。
5. 后续修复推送后，按当前 Trigger 判断是否自动复审，必要时再次手动请求。

仅有 GitHub 应用授权、网页开关已保存或普通 CI 通过，都不能代替实际 PR 审查结果。
Codex 审查也不等同于现有串口测试、平台构建或 GitHub 合并门禁。

## 与现有 CI 的关系

现有 Windows、Linux、macOS 工作流负责确定性的测试与构建，Codex 在 PR 上提供代码审查反馈。
如果后续需要强制合并条件，应根据项目实际流程配置 GitHub 合并规则，并在真实 PR 上验证。
本次未创建或合并 PR，也未把审查反馈配置成自动合并条件。
