# Linkport 官网内容与展示方案

用途：为后续官网提供定位、页面结构、可用文案、图示选择和能力表述依据。
本文件是内容与设计输入，**不是已经上线的官网或已经完成的官网实现**。

实现快照：2026-11-16，0.0.1 开发预览。技术事实以
[端与云服务架构](system-architecture.md) 和 [交互时序](interaction-sequences.md) 为依据。

## 1. 项目定位

Linkport 面向需要在自己的机器之间访问物理串口的开发者、设备调试者和实验室使用者。
通过设备配对和显式共享，在使用端创建本地虚拟串口映射，让现有串口工具能够访问远端串口；
同时提供真实 RX/TX 监听、发送和日志导出。

首屏应先让访问者看懂“串口在哪里、映射到哪里、怎么开始”。网络技术作为原理说明，
无需让用户先理解 QUIC、pkarr、ALPN 或 RFC 2217 才能看懂产品。

当前阶段应标注“开发预览”。目标平台为 Windows、macOS、Linux，平台运行和驱动验收范围
分别说明，不把构建通过直接写成所有环境均已可用。

## 2. 首屏文案草案

**主标题**

> 把远端串口，接到你的本机工具里。

**副标题**

> 配对自己的机器，将对方显式共享的串口映射到本机，继续使用熟悉的串口工具。
> 无需注册账号，也无需另装 VPN。

**主操作**

当前阶段使用“查看使用指南”。只有真实可访问的安装包发布入口准备好后，才改成
“下载开发预览”，并明确平台、架构和版本。

**次操作**

“了解连接原理”。源码或反馈入口在对应仓库公开访问条件确认后再加入。

**首屏配图**

采用一条清楚的数据链：

```mermaid
flowchart LR
    Tool["你熟悉的串口工具"] <--> Map["本机映射"]
    Map <-->|"加密连接"| Peer["已配对机器上的 Linkport"]
    Peer <--> UART["显式共享的物理串口"]
```

图下短说明：

> 机器间优先直接连接，必要时通过中继转发密文。共享哪些串口，由设备本机决定。

Windows 的 com0com 前置条件和 PTY 控制线限制应在下载区、快速开始和兼容性说明中可找到。
“本机映射”不能解释成所有串口电气特性、时序和控制线都与本地物理端口完全等价。

## 4. 三步使用说明

### 第一步：配对自己的机器

在一台机器上生成短期、单次邀请，在另一台导入。双方保存对方的设备公钥，无需中心账号。
当前是复制、粘贴邀请；没有实现扫码配对，不应在官网使用扫码作为已有操作演示。

### 第二步：选择要共享的串口

共享端用户显式勾选端口。未选择的串口不会出现在对端清单，新插入的设备默认不共享。
配对与共享是两次不同的授权动作。

### 第三步：建立本地映射，开始调试

使用端选择机器、串口和波特率，连接成功后，用本机串口工具打开映射路径；
也可以在 Linkport 中监听、发送和导出留存日志。

配图对应 [交互时序](interaction-sequences.md) 第 2、4、5 节。
官网可简化参与者和 API 名称，但应保留“显式共享”和“连接成功后”两个条件。

## 5. 功能展示

| 功能 | 适合展示的表述 | 应避免的误读 |
| --- | --- | --- |
| 无账号使用 | 设备自己生成身份，通过邀请配对 | 不代表匿名，也不代表不依赖任何基础设施 |
| 设备与共享管理 | 决定信任哪些机器、共享哪些串口，支持移除并断开 | 当前没有每个设备分别开放不同串口的细粒度 ACL |
| 本地串口映射 | 通过 PTY 或已配置的 com0com 端口对接入现有工具 | 不承诺所有串口工具、驱动和控制线特性完全等价 |
| 多会话 | 每条本机映射拥有独立生命周期与日志 | 不把代码中的数量上限当成已压测的并发能力 |
| 监听与发送 | 真实 RX/TX、文本/HEX、发送、暂停显示和导出 | 暂停不停止采集；日志有留存上限，不是无限录制 |
| 灵活连接 | 直连优先、中继兜底，可配置自己的服务或仅直连 | 不承诺所有 NAT 均能打洞或永远不经过中继 |
| 本机监听 | 无需共享、配对或映射即可直接监听本机串口 | 同一物理端口仍然独占 |

侧栏中的“插件”目前不能作为已经可用的插件生态宣传。自动重连、云端控制台、
远程开启共享、云端日志和账号找回也不属于当前功能。

## 6. 原理页的解释顺序

先回答三件事：

1. **怎么认出自己的机器？** 使用设备公钥作为身份，通过邀请建立信任。
2. **怎么找到它？** 使用保存的联系方式、局域网发现或所选地址发现服务。
3. **数据怎么过去？** 两端通过 iroh 建立加密连接，优先直连，需要时使用中继。

“去中心化”推荐表述：

> 设备自己保管身份密钥，配对和串口权限在设备本机决定。连接基础设施帮助两端接通，
> 并在需要时转发密文；你可以选择公共服务、配置自己的服务，或在可直接互通的网络中仅直连。

补充说明：默认公共发现和中继仍由第三方运营，因此不能把项目描述成基础设施每一层
都完全分布式、完全无服务器，或在任何服务器离线时仍保证所有机器互通。

需要详细图时使用 [端与云服务架构](system-architecture.md) 第 2 节和
[交互时序](interaction-sequences.md) 第 3 节；官网可把缓存超时、协议前导等实现细节放进开发文档。

## 7. 隐私与密钥页的必要内容

- 设备私钥保存在本机受限配置文件，当前尚未接入系统钥匙串或加密云备份。
- 完整私钥不返回桌面页面，不交给官网或中继。邀请不含私钥，但持有有效邀请者可以尝试配对，
  所以邀请应通过可信渠道分享。
- 串口内容在通信端点解密，中继负责运输密文。服务器仍可能观察连接公钥、IP、时间和转发量。
- 公共地址发现只发布中继地址；配对邀请和局域网发现可以含直接地址。
- 移除设备撤销本机授权并关闭连接；不会同步清除所有机器上的列表条目。
- 重置本机身份不会远程撤销旧私钥在其他机器上的权限；旧设备条目需要在各对端清理。
- 日志在本机有界留存并可导出，不提供当前不存在的云端保存、备份或合规审计承诺。

官网自身如果后续引入统计、反馈表单或第三方脚本，应按实际行为另行说明。
客户端的加密连接边界，不能自动视为未来网站也不收集任何访问数据。

## 8. FAQ 草案

**必须注册账号吗？**

不需要。每台机器在本地生成身份，通过邀请添加其他机器。

**两台机器要在同一个局域网吗？**

不必。客户端使用 iroh 尝试建立跨网络连接；实际直连与中继效果受网络环境影响，
当前开发预览还需要在目标网络中验证。

**必须自己部署中继吗？**

不是。默认可使用公共服务，也可配置自己的服务。公共服务的可用性和限额不由本项目承诺。

**中继会读取串口内容吗？**

正常协议下，中继承载端到端加密的数据，无法解密串口内容，但可以观察它参与的连接和流量元数据。

**知道设备 ID 就能访问串口吗？**

不可以。还需要获得本机配对授权，并且目标串口必须显式共享、可用且未被占用。

**Windows 要安装驱动吗？**

远端串口映射需要用户预先安装兼容的 com0com 驱动并配置端口对。直接本机监听不需要虚拟串口驱动。
Windows arm64 的驱动兼容性尚需验证。

**断线会自动恢复吗？**

底层连接有路径选择能力，但串口数据会话真正断开后，当前版本需手动重新连接。
不要把路径切换写成应用已经实现自动重连。

**日志会一直保存吗？**

不会。每会话留存最多 500 条 / 128 KiB，可导出当时仍保留的完整缓冲。当前没有自动落盘无限历史。

**官网关了还能用吗？**

官网不在正在运行的串口数据路径中；其不可用主要影响介绍、文档或下载入口。
连接基础设施和软件分发是另外的服务边界。

## 11. 官网与客户端的集成边界

首版官网可以独立静态托管。下载入口指向经确认的 Release 安装包，文档和变更记录来自仓库。
官网不需要保存用户设备身份，不提供浏览器直接控制串口、云端配对或云端设备管理。

上线前填入并核对实际资料：

- 正式域名、联系/反馈入口、可公开访问的源码或项目说明地址。
- 各平台可用安装包、校验和、签名状态、版本日期和系统前置条件。
- 真实可公开截图、图标、字体许可和项目许可证信息。
- 公共服务与自建服务的实际运营边界、隐私说明和当前开发阶段。
- 文案所引用的测试、平台验收和已实现能力，与对应版本一致。

这些是后续官网制作的输入，不在本次文档整理中购买云资源、创建站点或发布页面。
